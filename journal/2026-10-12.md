# 2026-10-12

*(This note covers the whole Task I modelling work done from 8 to 12 October.)*

## Objective

Build a fully scripted Abaqus/Explicit model of the automated SHPB with load inversion device (LID) for uniaxial tension (UT) specimens, following the lab conventions (`.geo` / `.dat` / `_paras.inp` files, `*INCLUDE`, `*PARAMETER`), and run the first simulations on the Euler cluster.

Task I: assess whether quasi-static force equilibrium is reached in UT specimens with short (19 mm) and long (40 mm) gauge sections at 100, 500 and 1000 s⁻¹, and find the loading speeds needed to reach 30 % engineering strain.

## Progress and Notes

### 1. The pipeline in one table

Everything lives in the repo folder `shpb-ut-equilibrium/`. Each step is a script, and the output of one step is the input of the next.

| Step | Script | Runs on | Input | Output |
|---|---|---|---|---|
| 0 | `scripts/pre/defeature_step.py` | PC, Python 3 + OpenCascade | SolidWorks STEP files | STEP files without the useless M4 holes (`*_noM4.step`) |
| 1 | `scripts/pre/make_materials.py` | PC, Python 3 | material parameters | `model/materials/*.dat` |
| 2 | `scripts/cae/build_bench.py` | Abaqus/CAE (File → Run Script), Python 2.7 | STEP files | meshed bench (`SHPB_UT19.cae`) + raw input file `model/geometry/_raw/SHPB_UT19_mesh.inp` |
| 3 | `scripts/pre/inp_to_geo.py` | PC, Python 3 | raw `.inp` from CAE | one flat `model/geometry/<PIECE>.geo` per piece |
| 4 | `scripts/pre/make_run.py` | PC, Python 3 | `studies/taskI/cases.csv` + templates | one self-contained folder `runs/<case_id>/` per simulation |
| 5 | `scripts/hpc/submit_study.py` + `run_array.sh` | PC → Euler | all case folders | Slurm job array on Euler, one Abaqus run per case |

The idea of the lab (my supervisor's advice): Abaqus/CAE is only used to mesh; the model itself is plain text, assembled with `*INCLUDE`, so that a whole study (6 cases) can be generated and launched with one command instead of clicking.

### 2. Repository and conventions

- Folders: `cad/native` (SolidWorks), `cad/step` (STEP exports), `model/geometry` (`.geo`), `model/materials` (`.dat`), `model/templates` (main `.inp` + `_paras.inp` templates), `scripts/{cae,pre,hpc,post}`, `studies/taskI/cases.csv`, `runs/` (generated, not versioned), `docs/` (assembly, materials, mesh).
- Case naming: `<specimen>_R<strain rate on 4 digits>_<index>`, e.g. `UT19_R0500_00`.
- Lab file conventions (from the tutorial video): a `.geo` file contains only nodes, elements and sets; a material `.dat` contains only the material keywords; the main `.inp` includes them; the values that change between runs are `*PARAMETER`s in `<case_id>_paras.inp`.
- Units: mm, N, s, MPa, t/mm³.
- Not versioned: `.geo` files and the raw CAE `.inp` (regenerated by the scripts), all Abaqus output files, `runs/`.
- Documentation written as tables in `docs/assembly.md`, `docs/materials.md`, `docs/mesh.md` and the project `README.md`.

### 3. Geometry: from SolidWorks to Abaqus

**What exists in CAD.** SolidWorks parts were available for the two specimens (UT and NT20 "Christmas tree"), the output bar and the load inverter (pusher). The striker and the input bar are plain cylinders and are created directly in the script (Ø20 mm; striker 5000 mm; input bar 6010 mm, Beerli et al. 2026).

**Problem: the `.SLDPRT` files cannot be imported** ("The file version is not supported": SolidWorks is newer than what Abaqus 2023 reads). Solution: export each part as STEP AP214 into `cad/step/`. The specimen was first extruded to 1.5 mm in SolidWorks (along +Z, from z = 0 to 1.5) → `XMas_UT_t1p5.step`.

**Placement in the global frame.** I chose to pull the specimen along **Y** (bar axes along Y). The placement was worked out from the CAD coordinates of the pockets and the bar axes:

| Instance | Rotation | Translation (mm) |
|---|---|---|
| PUSHER | +90° about X | none |
| INPUT_BAR | +90° about X | (0, 0, 7.85) |
| OUTPUT_BAR | +90° about X | (0, 155.713, 29.35) |
| UT19 (specimen) | +90° about Z | (356.2728, −1357.7622, 28.6) |
| STRIKER | +90° about X | (0, −6010, 7.85) |

Checks: the output bar axis is 21.5 mm above the input axis (Beerli 2026, fig. 5a); both pockets open upward and their floors are at the same height Z = 28.6, where the specimen lies (I first wrongly thought the specimen was sandwiched between the pusher and the output bar); the specimen is centred in both pockets (tips at Y = 124.013 and 201.700).

**Half model.** As in the lab's own models (Roth 2015, Beerli 2026), the bench is cut at the symmetry plane X = 0 and only X ≥ 0 is kept. In the script each piece is placed, then a boolean cut (`InstanceFromBooleanCut`) with boxes removes X < 0. A symmetry condition `XSYMM` is applied on the cut plane.

**Splitting the complex parts.** The round/rectangular bodies can be meshed with swept hexahedra, but the heads (pockets, teeth) cannot. So the pusher is cut at Y = 125 into `PUSHER_ROD` (hex) and `PUSHER_HEAD` (tet), and the output bar at Y = 100 into `OUTPUT_BAR` (hex) and `OUTPUT_HEAD` (tet). The two halves are glued back with ties.

**Problem: "Some regions cannot be Swept" on the output bar.** By reading the STEP file I found a tapped hole Ø8.5 × 27.5 mm at the far end of the bar. Solution (defeaturing): the round part of the output bar is replaced by a plain Ø20 × 6000 mm cylinder created in the script.

Final pieces (7): STRIKER, INPUT_BAR, PUSHER_ROD, PUSHER_HEAD, UT19, OUTPUT_BAR, OUTPUT_HEAD.

### 5. Meshing (`build_bench.py`)

| Piece | Element | Technique | Size |
|---|---|---|---|
| STRIKER, INPUT_BAR, PUSHER_ROD, OUTPUT_BAR | C3D8R (reduced integration, hourglass control) | swept | 5 mm along the axis, 2 mm in the section |
| UT19 | C3D8R | swept, structured in the gauge section | 0.5 mm in plane, 4 elements through the 1.5 mm thickness |
| PUSHER_HEAD, OUTPUT_HEAD | C3D10M (modified quadratic tetrahedra, made for contact in Explicit) | free | 2 mm (Roth 2015) |

The specimen is partitioned at the two ends of its straight gauge section (Y = 155.357 and 170.357, 15.000 mm long) so that the force can be measured exactly there.

**Problems with element types:**
- The heads were silently meshed with linear C3D4 tetrahedra (node/element ratio ≈ 0.2 gave it away): `setElementType` needs a **triplet** (hex, wedge, tet). Passing only one element type does not do what you think.
- "Default args are not fully supported…": mixing linear C3D8R and quadratic C3D10M in the same triplet is not allowed. I set the element type once by hand in the GUI and read the exact syntax in `abaqus.rpy`: `(UNKNOWN_HEX, UNKNOWN_WEDGE, C3D10M(secondOrderAccuracy=OFF, distortionControl=DEFAULT))`.
- **Method learned:** when the Python syntax of an operation is unknown, do it once in CAE and read `abaqus.rpy` (the current session's one, without a number). I used it again for the geometry repair and the virtual topology.

**Named groups** (defined on the geometry, so they survive a remesh):

| Name | Type | Use |
|---|---|---|
| `<PIECE>_ALL` | element set | section assignment |
| `XSYMM` | nodes on X = 0 | symmetry |
| `S_TIE` | surfaces at Y = 125 (pusher) and Y = 100 (output bar) | ties |
| `S_IMPACT`, `S_PUSH` | bar end faces | contact striker → input bar → pusher |
| `S_SKIN` | outer skin of the specimen and of the two heads | contact teeth ↔ pockets |
| `SEC_IN`, `SEC_OUT` | internal faces at the ends of the gauge section | force through the specimen |
| `GAUGE_ZONE` | elements of the straight gauge section | stresses/strains |
| `GAUGE_IN`, `GAUGE_OUT` | ~100 elements, 10 mm long, at 400 mm on input and output bars | virtual strain gauges (Beerli 2026) |
| `EXT_IN`, `EXT_OUT` | one node each, 12 mm apart on the specimen top face | virtual extensometer (DIC length of the sUT) |

### 6. From CAE to lab-style text files

- `build_bench.py` writes, besides the `.cae`, the raw input file generated by CAE (`writeInput`) in `model/geometry/_raw/`.
- `inp_to_geo.py` converts it into one flat `.geo` per piece: node coordinates are moved to the global frame (instance rotation + translation applied), labels are offset by n × 1 000 000 (piece n: STRIKER 1M, INPUT_BAR 2M, PUSHER_ROD 3M, PUSHER_HEAD 4M, UT19 5M, OUTPUT_BAR 6M, OUTPUT_HEAD 7M — so the first digit of a label in an error message tells the piece), and names are prefixed with the piece (`XSYMM` → `UT19_XSYMM`). A node set `<PIECE>_NALL` is added.
- Checked on the first run: 7 pieces, 223 795 elements, coordinates of the specimen in the expected box (Y 155–202, Z 28.6–30.1).

### 7. Main input file template (`model/templates/SHPB_UT_main.inp` + `SHPB_UT_paras.inp`)

| Section | Content |
|---|---|
| 0. Parameters | `*INCLUDE` of `<case_id>_paras.inp` (striker velocity, step time, output intervals) |
| 1. Mesh | `*INCLUDE` of the 7 `.geo` |
| 2. Materials | `*MATERIAL` + `*INCLUDE` of the 3 `.dat` |
| 3. Sections | one `*SOLID SECTION` per piece |
| 4. Ties | head (finer mesh) = secondary, rod = main; `ADJUST=YES`, `POSITION TOLERANCE=0.2` |
| 5. Contact properties | frictionless for bar ends; friction 0.2 for teeth/pockets (Roth 2015); hard normal contact (default) |
| 6. BCs and initial conditions | `XSYMM` on the 7 pieces; initial velocity +Y on all striker nodes. Specimen just lies in the pockets (nothing holds it from above on the real bench) |
| 7. Force sections | `*INTEGRATED OUTPUT SECTION` on `SEC_IN` / `SEC_OUT` → section force SOF2. Equilibrium ⇔ SOF2(SEC_IN) = SOF2(SEC_OUT); half model → real force = 2 × SOF2 |
| 8. Step | `*DYNAMIC, EXPLICIT`, no mass scaling; general contact **inside the step** (in Explicit, `*CONTACT` is history data) restricted to 4 surface pairs with `*CONTACT INCLUSIONS`; field outputs (specimen: 100 frames; whole bench: 20 frames) and history outputs every 1 µs (gauges LE22/S22, SOF of both sections, U2 of the extensometer nodes, energies incl. hourglass energy ALLAE) |

The template contains tokens (`__SPEC__`, `__CASE_ID__`, `__V_STRIKER_MS__`) that `make_run.py` replaces.

### 10. The stable time increment problem

**What it is.** Explicit integrates in tiny time steps; a wave must not cross more than one element per step, so Δt ≈ (smallest element dimension) / (wave speed ≈ 6 mm/µs). One single Δt is used for the whole model, so the worst element sets it for all 224 000 elements.

**What we had.** Δt = **5.5e-9 s** (≈ 730 000 increments for 4 ms), whereas the specimen layers (0.375 mm) should allow ≈ 6e-8 s. The 10 most critical elements were in the pusher head: flattened ("pancake") tetrahedra.

**Mass scaling rejected.** It would make the run faster by adding mass to the small elements, but mass (wave speed c = √(E/ρ), inertia forces) is exactly the physics studied in Task I. A colleague confirmed: no mass scaling in a dynamic study. (The lab tutorial uses it because that test is quasi-static.)

**Diagnosis.** I computed the smallest height (3 × volume / largest face) of each tetrahedron and located the 204 elements flagged by Abaqus:

| Cause | Flagged elements | Worst height |
|---|---|---|
| M4 hole (Ø3.3 drilled, with drill-point cone) in the pusher pocket floor, exactly on the symmetry plane X = 0 | 89 | 0.54 mm |
| M4 hole (Ø3.3, through) in the output head pocket floor, also on X = 0 | 45 | 0.68 mm |
| R0.5 / R1 / R1.5 fillets of the pocket teeth (strips 0.25–0.66 mm wide, 3.75 mm high) | 64 | **0.13 mm** |
| Thin strips (0.05–0.14 mm wide) of the cylindrical surface at the pusher rod/head junction (Y ≈ 130) | 2 | **0.10 mm** (they set Δt) |

(Median tet height ≈ 1.2 mm.)

**Fix 1 — remove the M4 holes (they are useless during the test).**
- First attempt in CAE (Geometry Edit → Face → Remove) on the half pusher head: the hole was "filled" but the part **lost its volume** (only a closed skin remained; the mesh controls then offered Quad/Tri surface elements) and "Shell → Solid" failed. Abandoned.
- Solution: remove the holes **in the STEP files, before Abaqus**, with OpenCascade (`BRepAlgoAPI_Defeaturing`) in `defeature_step.py`: it removes the faces of radius 1.65 mm and extends the neighbouring faces. Checks on the written files: still one valid solid, and the added volume equals the hole volume (pusher +101.2 mm³ = Ø3.3 × 11.5 mm + cone; output bar +62.0 mm³ = Ø3.3 × 7.25 mm). `build_bench.py` now imports `Inverter_new_noM4.step` and `Stange30mm_Step2_noM4.step`.

**Fix 2 — virtual topology on the two heads.** The mesher must respect every edge of the CAD; a 0.3 mm wide fillet strip with 2 mm elements forces flattened elements. Virtual topology tells the mesher to treat small faces/edges as merged with their neighbours (the real geometry is unchanged; nodes stay on the true surface; the fillets are no longer followed exactly, ~0.1–0.2 mm deviation at the tooth corners). Settings tested in CAE (Mesh → Tools → Virtual Topology → Automatic Create, checked with Preview) then scripted:
- edges shorter than 1.0 mm, faces smaller than 5.0 mm², faces with aspect ratio > 10 are merged;
- **"Keep blends" unchecked** (by default CAE protects fillets with radius < 2.1 mm, i.e. exactly ours);
- plus a minimum tet size of 1 mm (`minSizeFactor = 0.5`; before, 0.1 allowed 0.2 mm elements on small radii).

Smaller elements around the fillets were not an option: nicer elements, but an equally small Δt.

`build_bench.py` now prints the tet quality of each head. (Pitfall: in Abaqus/CAE, `sum()` is replaced by a version that rejects generators — "found 'generator'".)

**Result:**

| | Before | After |
|---|---|---|
| Elements in the heads | 30 886 + 11 755 | 24 307 + 8 753 (total model 214 214) |
| Smallest tet height | 0.102 mm / 0.174 mm | 0.431 mm / 0.388 mm |
| Initial stable Δt | 5.5e-9 s | **2.0e-8 s** (×3.7) |
| Most critical elements | 9/10 in the pusher head | one tet of the output head **and specimen elements**, equal |
| Max initial contact overclosure | 0.0070 mm | 0.0076 mm (contact not degraded) |
| Mass of the half model | 21.4882 kg | 21.4889 kg (+0.7 g = the two filled half-holes) |

The specimen now also limits Δt (≈ 2e-8 s instead of the expected 6e-8 s): it contains some elements ~3 times smaller than expected. Not investigated yet.

**Performance (short runs of 0.02 ms to measure the speed):**

| Mesh | Increments for 0.02 ms | Wall time | Δt during the run | Estimate for 4 ms |
|---|---|---|---|---|
| initial | 1 789 | 59 s (≈ 33 ms/increment) | ≈ 1.1e-8 s | ≈ 3.3 h |
| heads remeshed | 767 | 26 s (≈ 34 ms/increment) | ≈ 2.6e-8 s | ≈ 1.4 h |

(≈ 7.5 cores effectively used out of 8.)

**How long to simulate?** Discussion: the wave needs ≈ 1.23 ms to cross the 6 m input bar before anything happens at the specimen; equilibrium itself takes only a few round trips in the specimen (~0.05 ms); but reaching 30 % strain takes 0.30 / ε̇ (0.3 ms at 1000 s⁻¹, 0.6 ms at 500 s⁻¹, 3 ms at 100 s⁻¹). Idea kept in reserve: compute the step time per case (arrival ≈ 1.25 ms + 0.30/ε̇ + 0.2 ms margin, capped at the end of the pulse). Important physical point: the striker pulse lasts 2 × 5 m / 4720 m/s ≈ 2.1 ms, **shorter than the 3 ms needed for 30 % at 100 s⁻¹** — this striker cannot reach 30 % at 100 s⁻¹, which is itself an answer to Task I.

**Launching a whole study with one command.** `submit_study.py taskI` (on the PC) runs `make_run.py` for all cases, gathers them in a dated folder `runs/_submit/taskI_<date>/` with a `cases.txt` list, copies it to `$SCRATCH` and submits a Slurm **job array** (`run_array.sh`): one job per line of `cases.txt`, run in parallel. Each launch has its own dated folder, nothing is overwritten. A `--dry-run` option shows the commands without running them.
